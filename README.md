# Freight rate prediction

Predict the total posted rate in dollars for the 12,000 November-December loads supplied in the assessment.

## Setup

Use Python 3.12. From this folder on Windows:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-lock.txt
```

On macOS/Linux, replace `.venv\Scripts\python` with `.venv/bin/python`.

`requirements-lock.txt` pins the tested package versions. `requirements.txt` lists the permitted dependency ranges. All model fitting runs on the CPU.

## Run

```powershell
.venv\Scripts\python run.py
```

This runs the tests, audits the data, selects models, evaluates the frozen choice, checks unseen-city behavior, reproduces the follow-up Ridge benchmark, trains on all labeled rows, exports both prediction files, and runs the supplied scorer. It uses four CPU threads by default; change this with `--threads 2` if needed.

To inspect or rerun a particular stage:

```powershell
.venv\Scripts\python -m freight.audit
.venv\Scripts\python -m freight.experiment select
.venv\Scripts\python -m freight.experiment evaluate
.venv\Scripts\python -m freight.experiment stress
.venv\Scripts\python -m freight.benchmark
.venv\Scripts\python -m freight.train
.venv\Scripts\python -m freight.predict
.venv\Scripts\python score.py --predictions validation_predictions.csv --december-predictions december_predictions.csv
```

`select` freezes the chosen models and parameters in `artifacts/selection.json`. `evaluate`, `stress`, and `train` read that file. Changing the candidate set after reading holdout results would turn the holdout into another tuning set.

## Validation plan

The labeled data covers January-October 2025. Final predictions cover November-December, so validation uses whole future months:

| Use | Train through | Evaluate on |
| --- | --- | --- |
| Model selection | April 30 | May-June |
| Model selection | June 30 | July-August |
| Final local evaluation | August 31 | September-October |
| Submission fit | October 31 | November-December, labels unavailable |

Choose models using mean dollar MAE across the two selection windows. Also report RMSE, WAPE, and R-squared. Keep every evaluation label, including unusually large or small rates. The provided scorer does not measure accuracy; Spotter calculates the final metrics privately.

The fixed December scenario omits quote signals, market indices, and coordinates. Its model must be evaluated using the same available inputs. Do not invent future market values or copy quotes from unrelated loads.

| --- | ---: |
| Equipment/distance baseline | $169.70 |
| Core inputs | $138.31 |
| Full inputs including quote signal | $126.63 |
| Inputs excluding quote signal, selected | $115.38 |

September-October evaluation contains 9,523 loads and uses models fitted on the preceding 38,477 loads:

| Model | MAE | RMSE | WAPE | Median absolute error |
| --- | ---: | ---: | ---: | ---: |
| Baseline | $140.54 | $638.82 | 5.87% | $62.83 |
| Selected main model | $125.86 | $639.05 | 5.26% | $50.86 |
| Selected December model | $125.20 | $638.68 | 5.23% | $51.29 |

The main model reduces holdout MAE by 10.4%, while RMSE is effectively unchanged. The largest 1% of absolute errors account for about 96.5% of squared error. These rows remain in the reported scores. Mean prediction bias is -$99.10, so underprediction is a limitation, especially for large loads. No correction was fitted using holdout residuals.

The core model is slightly better on this particular holdout. The main model remains `no_quote`, as chosen on the earlier windows; switching because of this result would invalidate the holdout's role.

In the city exclusion stress test, the main model achieves $109.19 MAE against $128.58 for the baseline on 1,671 loads. The core model achieves $143.69. The ordinary temporal holdout contains no new cities and only 21 unseen-lane loads, so its unfamiliar-route slice alone is too small to support a strong conclusion.

## Modeling decisions

The baseline uses median rate per mile within equipment and distance bands. The learned models use CatBoost with a small, fixed configuration: 700 trees, depth 6, learning rate 0.05, seed 42. There is no large parameter search or early stopping against the final holdout.

The target is dollars per mile. Each training row is weighted by its distance, so weighted absolute error in dollars per mile is proportional to absolute error in total dollars. Predictions are multiplied by the load's distance. MAE is the selection criterion because a few extreme rates otherwise dominate squared error. RMSE and all original targets are retained in the evaluation.

Three feature sets test the inputs rather than assume that all supplied columns help:

| Model | Available inputs |
| --- | --- |
| `full` | Load details, supplied coordinates, market index, quote signal |
| `no_quote` | The same inputs, excluding quote signal |
| `core` | Pickup, delivery, distance, equipment, weight, date; city coordinates looked up from training only |

Features include directed lanes, equipment, distance, inverse distance, weight, changes in coordinates, weekday, and annual sine/cosine terms. IDs and the target never enter the feature matrix. CatBoost handles categorical values and missing numeric features. City lookups are refitted inside each training split. The core model ignores supplied coordinates even during validation, matching the December input contract.

## Data findings and handling

- The 48,000 labeled rows cover January 1-October 31, 2025. The 12,000 final rows cover November 1-December 31.
- Development data has 300 missing weights, 292 nonpositive weights, and 374 missing market indices. Nonpositive or nonfinite weights become missing; their signs are not silently corrected. Missing-value flags are included.
- Final inputs have 165 missing weights, 145 nonpositive weights, and 249 missing market indices. There are eight new cities and 1,461 loads on lanes absent from development data.
- `quote_signal` switches between positive and negative relationships with rate per mile across months, with almost no relationship in August. Its creation time and meaning are unspecified. The ablation checks whether it remains useful when predicting later months.
- Coordinates are internally consistent for each training city. They are used as supplied, without external geocoding or assumptions that city names identify real coordinates.
- Unusually high and low target rates are flagged in the audit, but are not deleted or clipped. The robust objective reduces their training influence while evaluation still counts their full errors.

## Follow-up linear benchmark

A Ridge regression comparison was added after the original holdout results had been inspected. It uses only the original May-June and July-August selection windows. It does not replace the frozen model selection, alter the submission predictions, or claim a new blind holdout result.

| Method | May-June MAE | July-August MAE | Mean MAE |
| --- | ---: | ---: | ---: |
| Equipment/distance baseline | $197.93 | $141.47 | $169.70 |
| Selected CatBoost, no quote signal | $119.30 | $111.45 | $115.38 |
| Ridge, same input features | $118.82 | $180.05 | $149.44 |

Ridge is competitive in the first window but performs worse in the second. This fixed comparison supports keeping CatBoost; it does not establish that every possible linear model or parameter choice would perform worse.

The Ridge benchmark uses the same `no_quote` feature set. Median imputation, numeric standardization, and one-hot category encoding are fitted within each training window. Unfamiliar categories are ignored by the encoder. The fixed settings are `alpha=10`, the `lsqr` solver, tolerance `1e-6`, and a maximum of 10,000 iterations; there is no parameter search. The target is rate per mile, with distance-squared weights normalized to mean one, making the data-fit term proportional to squared total-dollar error. Ridge's squared-error objective differs from CatBoost's MAE objective. All targets remain in the evaluation. See the [Ridge documentation](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.Ridge.html) for the estimator's objective.

## Limits

The final targets are unavailable, so local results cannot establish November-December accuracy. The scorer confirms the submission format, not forecast quality. The final data also has more missing fields and cities absent from training.

The city stress test excludes six cities chosen by a fixed alphabetical rule, fits on January-June, then evaluates their July-August loads. It is diagnostic only and does not change the selected model. It approximates the problem of new cities but cannot prove accuracy on the eight actual new cities.

The December chart is a conditional estimate with fixed load details. Its core model has no observed future market index or quote signal. The data contains no previous December, so December seasonality and holiday surcharges cannot be validated. The annual terms allow a recurring seasonal pattern; this is an assumption, not evidence about Christmas demand.

Only fields available when a quote is requested should be used in deployment. `market_index` is assumed available because it is supplied for final predictions; its publication timing would need confirmation before production use. This assessment provides a reproducible batch pipeline, not an online service.

Useful implementation references: [CatBoost missing values](https://catboost.ai/docs/en/concepts/algorithm-missing-values-processing), [CatBoost regression objectives](https://catboost.ai/docs/en/concepts/loss-functions-regression), and [time-ordered evaluation](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html). Splits here use calendar boundaries because the number of loads varies by day.
